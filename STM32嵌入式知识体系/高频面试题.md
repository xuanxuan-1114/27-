# STM核心知识
## STM32上电后首先执行main函数吗？
不是。CPU首先从向量表读取MSP初值和复位入口地址，然后执行 `Reset_Handler`，完成 `.data` 搬运、`.bss` 清零和系统初始化，最后进入 `main()`。
## 全局变量为什么断电后丢失，但重新启动又有初始值？
变量运行时保存在RAM中，断电后会丢失；非零初始值保存在Flash中，启动代码重新把初始值复制到RAM。
## Bootloader如何跳转到应用程序？
- 检查应用程序栈顶是否合法；
- 关闭相关中断和外设； 
- 设置向量表地址；
- 读取应用程序初始MSP；
- 读取应用程序复位入口；
- 设置MSP；
- 跳转到应用程序。
## 为什么外设必须开启时钟
STM32为了降低功耗，默认不会给所有外设提供时钟。
如果没有开启外设时钟：
- 配置寄存器可能无效；
- 外设不会工作；
- 读写结果异常。
## STM32F103为什么通常配置为72 MHz？
STM32F103常见型号的最高系统工作频率为72 MHz。使用8 MHz HSE经过PLL 9倍频即可得到72 MHz。
## PCLK1为36 MHz，为什么TIM2可能是72 MHz？
当APB1预分频不为1时，连接到APB1的定时器时钟会自动变为PCLK1的2倍。
## HSI和HSE有什么区别？
HSI位于芯片内部，成本低、启动快，但精度通常较低；HSE使用外部晶振，精度和稳定性通常更好，但需要额外元件。
## 推挽和开漏有什么区别
推挽可以主动输出高、低电平；开漏只能主动拉低，高电平依靠上拉电阻产生。I²C为了支持多设备共享总线，使用开漏结构。
## 中断函数为什么要尽量短？
因为中断执行期间会延迟主程序和同级或低优先级中断。执行时间过长可能导致数据丢失、控制延迟和实时性下降。
## 中断服务函数里执行耗时操作的后果
**阻塞低优先级中断**：导致数据丢失或系统响应延迟。
**影响任务调度**：任务超时或系统响应缓慢的情况。
**导致系统崩溃**
## volatile能保证中断与主程序的数据安全吗？
不能。`volatile`只保证每次访问实际内存，不保证复合操作的原子性，也不解决竞争条件。
## 中断嵌套是什么意思？
高抢占优先级中断可以打断正在执行的低抢占优先级中断。高优先级中断完成后，再继续执行原来的低优先级中断。
## UART为什么要接地
接收端判断高低电平需要共同的电压参考。如果两端不共地，电平参考可能不同，导致通信错误甚至损坏器件。
## UART为什么会出现粘包和拆包
UART是连续字节流，没有数据包边界。接收函数一次得到的数据不一定对应完整协议帧，所以需要通过帧头、长度和校验恢复帧边界。
## UART丢数据怎么排查
检查：
1. 波特率和时钟；
2. TX/RX连接；
3. 是否共地；
4. 中断是否及时读取；
5. 是否发生ORE；
6. 缓冲区是否过小；
7. 中断是否执行过长；
8. DMA配置；
9. 协议解析是否错误；
10. 电平标准是否一致。
## SPI为什么读取时也需要发送数据？
因为SPI时钟由主机产生，发送和接收同时进行。主机必须发送虚拟数据产生时钟，从机才能移出返回数据。
## SPI通信失败如何排查？
检查：
1. CPOL和CPHA；
2. MSB/LSB发送顺序；
3. 片选极性及时序；
4. SPI频率是否过高；
5. MOSI/MISO是否接反；
6. 是否共地；
7. 数据长度；
8. 命令格式；
9. 使用逻辑分析仪观察波形。
## 看门狗有什么作用？
看门狗用于检测程序卡死、跑飞或任务失去响应。如果程序未在规定时间内喂狗，看门狗会自动复位系统，使设备恢复运行。
## 为什么不能在定时器中断中无条件喂狗？
因为主程序即使已经卡死，定时器中断仍可能继续喂狗，导致看门狗无法发现系统故障。
## IWDG和WWDG有什么区别？
IWDG使用独立低速时钟，只要求在超时前喂狗；WWDG使用窗口机制，喂得太早或太晚都可能复位，更适合检测程序运行节奏异常。
## ROM和RAM
**ROM**：只读存储器，一种非易失性存储器，断电后数据不会丢失。主要用于存储固定的程序和数据，例如系统启动代码，固件和嵌入式设备的控制程序。
**RAM**：随机存储器，一种易失性存储器，断电后数据会丢失。它主要用于存储运行时的临时数据，例如变量、堆栈和缓存。
## 一个32位寄存器，里面每个bit对应一个gpio状态，比如bit7，你怎么判断这个gpio是1还是0
```c
if (reg & (1U << 7))
{
    //bit7 = 1
}

```
补充
```c
// 判断 bit7
reg & (1U << 7);

// 将 bit7 置 1
reg |= (1U << 7);

// 将 bit7 清 0
reg &= ~(1U << 7);

// 将 bit7 翻转
reg ^= (1U << 7);

// 取出 bit7，得到明确的 0 或 1
uint8_t bit7 = (reg >> 7) & 1U;
```
